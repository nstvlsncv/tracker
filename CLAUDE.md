# Трекер

Личный веб-трекер недель, задач, целей и привычек. React + TypeScript + Vite, данные и вход в Supabase.

## Источники правды

1. **Макеты из Фигмы** (скриншоты присылает владелица продукта). При расхождении с `SPEC.md` делаем как в макете.
2. `SPEC.md`: поведение, формулы, тексты. Местами устарел, см. «Отступления от SPEC.md» ниже.
3. `design-tokens.json`: единственный источник цветов, отступов, радиусов и шрифтов.

## Команды

- `npm run dev`: дев-сервер на http://localhost:5173. Только в режиме разработки: `/dev` (витрина компонентов) и `/dev/app` (экраны приложения на демо-данных, без входа и без базы)
- `npm run build`: проверка типов и сборка
- `npm test`: unit-тесты (vitest)
- `npm run lint`: oxlint
- `npm run tokens`: пересобрать `src/styles/tokens.css` из `design-tokens.json` (запускается сам перед dev и build)

## Деплой

Пуш в `main` сам выкатывается на прод (Vercel подключён к GitHub). Поэтому:

- Все изменения сначала делаются и проверяются локально.
- **Перед пушем в `main` и любым деплоем на прод нужно спросить владелицу и дождаться явного согласия.** Коммитить локально можно, пушить без отмашки нельзя.
- **При каждой выкладке на прод добавляется запись в `src/data/changelog.ts`** (новая сверху, дата выкладки). Запись пишется в момент выкладки, после отмашки владелицы: в истории не должно быть версий, которых ещё нет на проде. Она показывается в Профиле в блоке «История версий». Текст по-русски, немного смешной, но понятно объясняющий, что изменилось. Без длинных тире и восклицательных знаков.

## Правила кода

- Иконки: набор Phosphor (`@phosphor-icons/react`), начертание bold задаётся один раз в `App.tsx`.
- Цвета, отступы и радиусы только через CSS-переменные из токенов, причём семантические (`--bg-primary`, `--space-md`), не `--core-*`. Размеры самих компонентов (высота кнопки, диаметр чекбокса) задаются числами.
- `src/styles/tokens.css` генерируется, руками не правится. Нужен новый токен: добавь его в `design-tokens.json`.
- Стили компонентов: CSS Modules рядом с компонентом. Текстовые стили: глобальные классы `t-heading-1`, `t-body-md` и т. д.
- Тексты интерфейса: русский, на «ты», без длинных тире.
- Формулы лежат в `src/lib/metrics.ts` и покрыты тестами. Даты в формулах: строки `yyyy-MM-dd`.

## Отступления от SPEC.md

- **Регистрации и восстановления пароля нет.** Только вход по email и паролю. Пользователей заводят вручную в Supabase: Authentication → Users → Add user (галочка Auto Confirm User). Строка в `profiles` создаётся приложением при первом входе. Причина: встроенная почта Supabase не умеет слать письмо с кодом, свой почтовый сервис не подключён.
- **Шрифт один:** Unbounded везде, включая цифры. IBM Plex Mono не используется.
- **Строки списков:** иконки редактирования нет, переименование включается кликом по строке (кроме чекбокса и корзины). Корзина: IconButton Danger / Ghost 32px с иконкой 16px, видна при наведении.
- **Danger / Ghost при наведении:** красная заливка и белый текст. То же у «Выйти» в боковом меню.
- **Шапка экрана:** от неё до содержимого 24px (`PageHeader`). Подсказки на месте пустых списков цветом плейсхолдера.
- **Кнопки:** размеры 32/40/48, стили Accent (Main, Secondary, Ghost) и Danger (Main, Ghost), состояния Default, Hover, Pending, Focus, Disabled, Pressed. Скругление 8/12/16px по размеру, не «пилюля».
- **Чекбокс:** только круглый 32×32.
- **Инпуты:** высота 48px.
- **Пунктирных рамок нет нигде.** «Добавить …» в списках: кнопка Accent / Secondary.
- **Будущие дни** показывают процент, как остальные (без слова «план»). День без задач показывает 0%, а не прочерк.
- **Сегодняшний день на Неделе:** карточка с обратными акцентами (чёрный фон, белый текст). Внутри неё семантические токены переназначены в `DayCard.module.css`, поэтому чекбоксы, донат и кнопки перекрашиваются сами.
- **Загрузка:** вместо пустой страницы показываются заглушки-силуэты: всего приложения (`AppSkeleton`), экрана входа (`LoginSkeleton`), блоков Недели. Каждому новому экрану нужны свои заглушки. Посмотреть их можно на `/dev/skeleton/app` и `/dev/skeleton/login`.
- **Неделя:** в шапке справа две кнопки. «Добавить задачу» (Secondary) открывает модалку с календарём для задачи на любой день. Кнопка с текущей неделей (Accent / Main) открывает под собой календарь, где выбирается неделя целиком; недели с данными помечены точкой (`CalendarPicker`). Кнопки «Добавить неделю» нет: на любую неделю можно перейти из календаря. Ещё, сегодняшний день выделен только цветом числа, карточки дней листаются обычной прокруткой без кнопок-стрелок, кнопка «Добавить задачу» прижата к низу карточки, статистика стоит в самом низу, под карточками дней. Подписи статистики: «ср. прогресс», «лучший день», «вып. целей».
- **Модалки:** ширина 650px, 120px от верха, крестик снаружи справа сверху, без внутреннего скролла. Выбранное в календаре значение пишется в кнопку подтверждения («Добавить 5–11 октября 2026»).
- **Тосты:** сверху по центру, 48px от верха.
- **Фоны:** страница белая (`--bg-surface`), карточки-секции `--bg-primary`, вложенные карточки белые.
- **Главная:** первая карточка «прогресс дня», не «прогресс недели».
- **История привычки:** последние 12 месяцев, круглые точки, подписи дней только справа.
- **Профиль:** есть поле «Фамилия» (`profiles.last_name`).

## Адаптив

SPEC.md считал мобильную версию вне скоупа, но владелица попросила адаптивы. Две границы:

- **до 1024px (планшет):** боковое меню сжимается в полосу с иконками, поля страницы 16px.
- **до 640px (телефон):** меню становится нижней панелью в духе iOS (белая непрозрачная, без размытия, иконка и подпись, активный раздел выделен цветом). Иконки разделов не меняют начертание, а коротко оживают при каждом нажатии на раздел, в том числе на уже открытый (подпрыгивание, перелистывание, оборот, кивок). При загрузке страницы анимации нет. Кнопки «Выйти» в ней нет: на телефоне выход на экране Профиля. Кнопки в шапке во всю ширину друг под другом, главная сверху, статистика в два столбца, карточки дней шириной 82vw, в модалках кнопки друг под другом.
- До 800px крестик модалки стоит над её правым верхним углом (сбоку нет места).
- На сенсорных экранах (`hover: none`) корзина в строках видна всегда.
- На сенсорных экранах текст в полях ввода 16px (иначе iOS приближает страницу), а инлайн-поле добавления один раз прокручивается в середину экрана (не на каждое изменение экрана: это вызывало дёрганье). Кнопка «Готово» на клавиатуре и скрытие клавиатуры сохраняют введённое и закрывают поле.
- Точки на экране входа на планшете и телефоне неподвижны.

Новые экраны нужно сразу проверять на 375px и 820px.

## Устройство

- `src/layout/AppShell.tsx`: боковое меню и место под экран.
- `src/data/`: задачи и цели. `PlannerProvider` держит их на время сеанса и сохраняет оптимистично (интерфейс меняется сразу, при ошибке откат и тост). Откуда брать данные, решает `PlannerApi`: `supabaseApi` в приложении, `memoryApi` для `/dev/app`.
- `src/pages/`: экраны. Сделаны вход и Неделя; Главная и Привычки пока заглушки (`ComingSoon`), в Профиле пока только история версий и выход для телефона.
- Проверять экраны в браузере без пароля можно на `/dev/app`. Настоящий вход и запись в Supabase проверяет владелица.

## Supabase

- Схема: `supabase/schema.sql`. Применяется вручную через SQL Editor, файл можно запускать повторно.
- Ключи: `.env.local` (в git не попадает), образец в `.env.example`. В коде только publishable-ключ.
- Доступ к данным закрыт Row Level Security: каждый видит только свои строки.
