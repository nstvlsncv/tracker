> Документ для Claude Code. Рядом лежит `design-tokens.json` — единственный источник дизайн-переменных. Не хардкодь цвета, отступы, радиусы и шрифты: всё берётся из токенов (через CSS-переменные или конфиг Tailwind).

## 0. Как читать этот документ

- **[РЕШЕНО]** — зафиксированное продуктовое решение, менять нельзя без согласования.
- **[ДОПУЩЕНИЕ]** — разумное решение по умолчанию, которое не обсуждалось явно. Реализуй так, но вынеси в константы, чтобы легко поменять.
- **[ОТКРЫТО]** — вопрос не решён. Реализуй указанный вариант по умолчанию и оставь `// TODO(open):` в коде.

## 1. Продукт

Личный веб-трекер недель, задач, целей и привычек. Один пользователь = один аккаунт, данные приватные. Референс по смыслу: Google-таблица PlanerGO (недельный планер с донатами прогресса), но как нормальное веб-приложение.

- **Платформа:** десктопный веб. [РЕШЕНО] Мобильная версия вне скоупа, но вёрстка не должна ломаться при ширине окна от 1024px.
- **Язык интерфейса:** русский. Обращение на «ты».
- **Название:** «Трекер» (рабочее).
- **Дневник, финансы, геймификация уровня Habitica — вне скоупа.** [РЕШЕНО]

### 1.1 Рекомендуемый стек [ДОПУЩЕНИЕ]

- React + TypeScript + Vite
- Supabase: Postgres, Auth (email OTP-коды и пароль из коробки, бесплатный тариф), Row Level Security
- Отправка писем: встроенная в Supabase или Resend (бесплатного тарифа хватит с запасом)
- Стили: CSS-переменные, сгенерированные из `design-tokens.json`, или Tailwind с темой из токенов
- Иконки: Tabler Icons (outline)
- Даты: date-fns с локалью `ru`, неделя начинается с понедельника

## 2. Дизайн-система

### 2.1 Токены

Файл `design-tokens.json`, две группы:

- `core` — примитивы (сырые значения). **В компонентах напрямую не используются.**
- `semantic` — семантика, ссылается на `core` через `{core.X.Y}`. **Компоненты используют только её.**

Сгенерируй из токенов CSS-переменные вида `--bg-primary`, `--text-secondary`, `--radius-lg`, `--space-md` и т. д.

### 2.2 Типографика

- **Unbounded** — для ВСЕГО текста, включая мелкий UI. [РЕШЕНО] Подключить с Google Fonts, начертания 400/500/600/700, с кириллицей.
- **IBM Plex Mono** — только для цифр: проценты, счётчики, серии, числа месяца в карточках дней, статистика. Начертания 500/600.
- Курсива нет нигде (у Unbounded его нет).
- Стили текста берутся из `semantic.typography`. Line-height задаётся в пикселях.
- Если на 12px Unbounded читается плохо, сообщи, не меняй шрифт молча.

### 2.3 Цвет: правила

- Интерфейс монохромный, нейтральная палитра без тёплого или холодного подтона (R=G=B). Акцент чёрный.
- **Зелёный** (`semantic.habit.streak-accent`) используется ТОЛЬКО для серии привычки, когда привычка выполнена сегодня. Это сознательная игровая механика. Больше нигде. [РЕШЕНО]
- **Красный** (`semantic.status.danger.*`) только для: ошибок в формах, кнопки «Выйти» в сайдбаре, блока «Опасная зона».
- Оранжевый (warning) зарезервирован, сейчас не используется.

### 2.4 Слои и поверхности

| Слой | Токен |
|---|---|
| Фон страницы | `bg/primary` |
| Сайдбар | `bg/primary` + граница `border/subtle` |
| Карточка-секция (блок «Цели недели» и т. п.) | `bg/secondary` |
| Вложенная карточка внутри секции (статистика, хитмап) | `Base/white` |
| Модалка | `Base/white` + `effects/shadow-lg`, подложка `effects/overlay` |

### 2.5 Радиусы и отступы

- Секции и карточки: `radius/lg` (16). Вложенные карточки: `radius/md` (12). Инпуты: `radius/md`. Кнопки и пилюли: `radius/full`.
- Отступы только из `semantic.space`. Внутренний паддинг секции: `space/lg` (24).

## 3. Компоненты

Для каждого компонента реализуй состояния: default, hover, pressed, focus-visible (обводка `effects/focus-ring` 2px с отступом 2px), disabled.

### 3.1 Button
- `primary`: фон `accent/default`, текст `accent/foreground`. hover `accent/hover`, pressed `accent/pressed`, disabled фон `accent/disabled` и текст `text/disabled`.
- `secondary`: фон `Base/white`, граница `border/subtle`, текст `text/primary`. hover фон `bg/secondary`.
- `ghost`: без фона и границы, текст `text/secondary`. hover фон `bg/secondary`.
- `danger`: фон `status/danger/text`, текст белый.
- Размеры: sm 32px, md 40px, lg 48px. Опционально иконка слева.

### 3.2 Кнопка «+ Добавить …» внутри списков
Внизу каждого списка (цели, задачи, привычки): кнопка с пунктирной границей `border/default`, иконка `+`, текст «Добавить цель» / «Добавить задачу» / «Добавить привычку». Визуально тише элементов списка.

### 3.3 Checkbox (круглый) [РЕШЕНО]
- Круг 20px (в карточках дня 14px).
- Не отмечен: граница 1.5px `border/default`, фон белый.
- Отмечен: фон `accent/default`, белая галочка.
- hover: граница `border/strong`.
- Клик переключает состояние сразу (оптимистичное обновление).

### 3.4 Элемент списка (задача, цель)
- Чекбокс + текст.
- Выполнено: текст `text/disabled` + зачёркивание.
- **Сортировка: невыполненные сверху, выполненные снизу.** [РЕШЕНО] Внутри группы по времени создания. При отметке элемент переезжает с короткой анимацией.
- На hover справа появляются иконки «редактировать» и «удалить».

### 3.5 Input
- Высота 40px, фон белый, граница `border/subtle`, радиус `radius/md`.
- Лейбл над полем, стиль `caption`, цвет `text/secondary`.
- focus: граница `accent/default`.
- error: фон `status/danger/bg`, граница `status/danger/border`, под полем иконка `alert-circle` и текст ошибки `status/danger/text`.
- Поле пароля: иконка-глаз справа, показать или скрыть пароль.

### 3.6 Поле кода (OTP)
6 отдельных ячеек ~44×52px, цифры шрифтом IBM Plex Mono. Автопереход к следующей ячейке, поддержка вставки кода целиком, Backspace уходит назад. Заполненная ячейка с границей `accent/default`.

### 3.7 Donut (кольцо прогресса)
- Заливка `accent/default`, трек `bg/tertiary`, процент в центре (`number-sm` или `number-lg`).
- Будущий день: пунктирная окружность `border/default`, в центре слово «план», без процента.

### 3.8 Stat card
Белая карточка: крупное число (`number-lg`) и подпись снизу (`caption`, `text/tertiary`).

### 3.9 Week switcher (пилюля)
Белая пилюля с границей: `‹` · «14–20 сентября 2026» · `›`. Стрелки листают по одной календарной неделе.

### 3.10 Modal
Центрированная карточка шириной 440px. Заголовок, контент, кнопки справа внизу: «Отмена» (secondary) и основное действие (primary или danger). Закрытие по Esc, по клику на подложку и по крестику. Фокус-ловушка внутри модалки.

### 3.11 Toast
Внизу справа, автоскрытие через 4 секунды. Для удаления добавляется кнопка «Отменить».

## 4. Каркас приложения

### 4.1 Сайдбар (на всех экранах после входа)
- Ширина 240px, фиксирован слева, внутри отступы, скругление `radius/lg`.
- Сверху логотип: иконка `hexagon` и «Трекер».
- Пункты: **Главная** (`home`), **Неделя** (`calendar`), **Привычки** (`repeat`), **Профиль** (`user`).
- Активный пункт: фон `bg/secondary`, текст `text/primary`, medium. [РЕШЕНО] Не чёрная заливка.
- Внизу через разделитель: **Выйти** (`logout`), цвет `status/danger/text`. Выход сразу, без подтверждения, редирект на вход.

### 4.2 Роутинг
| Путь | Экран | Доступ |
|---|---|---|

| `/week/:isoWeek?` | Неделя (по умолчанию текущая) | авторизованный |
| `/habits` | Привычки | авторизованный |
| `/profile` | Профиль | авторизованный |

Гость на защищённом пути уходит на `/login`. Авторизованный на гостевом пути уходит на `/`.

## 5. Экраны авторизации

Общий layout: без сайдбара, по центру логотип и карточка `bg/secondary` шириной 380px.

### 5.1 Вход `/login` (стартовый экран) [РЕШЕНО]
- Заголовок «С возвращением», подзаголовок «Войди, чтобы продолжить».
- Поля: Email, Пароль.
- Ссылка «Забыли пароль?» справа под паролем.
- Кнопка «Войти» (primary, на всю ширину).
- Снизу: «Нет аккаунта? Зарегистрироваться».

**Сценарии:**
| Ситуация | Поведение |
|---|---|
| Пустые поля | Кнопка неактивна |
| Неверный email ИЛИ пароль | **Одно общее сообщение** «Неверный email или пароль», оба поля в состоянии error. Нельзя раскрывать, существует ли email. [РЕШЕНО] |
| 5 неудачных попыток подряд | [ДОПУЩЕНИЕ] Блок на 5 минут: «Слишком много попыток. Попробуй через 5 минут» |
| Ошибка сети | Toast «Не удалось подключиться. Проверь интернет» |
| Успех | Редирект на `/` |

### 5.2 Регистрация `/register`, 3 шага [РЕШЕНО]
Сверху прогресс-бар из трёх сегментов, пройденные `accent/default`, остальные `bg/tertiary`. На шагах 2 и 3 ссылка «Назад».

**Шаг 1. Email**
- «Какой у тебя email?» / «Пришлём код для подтверждения».
- Поле Email.
- **Чекбокс согласия** (квадратный, не круглый): «Согласна(ен) с Политикой обработки персональных данных и Пользовательским соглашением». Оба названия ссылками на `/privacy` и `/terms`. [РЕШЕНО]
- Кнопка «Отправить код» неактивна, пока email невалиден или чекбокс не отмечен.
- Сохранить в БД факт согласия: дату и время, версию документов.

| Ситуация | Поведение |
|---|---|
| Невалидный формат | Ошибка «Проверь email» |
| Email уже зарегистрирован | Ошибка «Аккаунт уже есть. Войти?», «Войти?» ведёт на `/login` с подставленным email. [РЕШЕНО: показывать явно на регистрации] |
| Успех | Отправить 6-значный код, перейти на шаг 2 |

**Шаг 2. Код**
- «Введи код» / «Отправили на {email}».
- Поле OTP из 6 ячеек. При вводе 6-й цифры проверка запускается автоматически.
- «Не пришло? Отправить ещё раз» неактивно с таймером 60 секунд: «Отправить ещё раз (0:47)».

| Ситуация | Поведение |
|---|---|
| Неверный код | Ячейки в error, «Неверный код. Осталось попыток: N». Всего 3 попытки |
| Попытки закончились | Код аннулируется, показать состояние «код истёк» |
| Код истёк (10 минут) | Заголовок «Код истёк», подзаголовок «Прошло больше 10 минут», ячейки неактивны, кнопка «Отправить новый код» |
| Успех | Шаг 3 |

**Шаг 3. Имя и пароль**
- «Придумай пароль» / «Email подтверждён ✓».
- Поля: Имя, Пароль, Повтори пароль.
- **Живой чеклист под паролем**, пункты отмечаются по мере ввода:
  - Минимум 8 символов
  - Есть цифра
  - Есть заглавная буква
- Невыполненный пункт: серый пустой круг. Выполненный: чёрный круг с галочкой.
- «Создать аккаунт» неактивна, пока не выполнены все пункты, пароли не совпадают и имя пустое.

| Ситуация | Поведение |
|---|---|
| Пароли не совпадают | Поле «Повтори пароль» в error: «Пароли не совпадают». Проверять при потере фокуса и при сабмите |
| Успех | Создать аккаунт, автоматически залогинить, редирект на `/` с пустыми состояниями |

### 5.3 Восстановление пароля `/reset-password`
Тот же 3-шаговый паттерн, что у регистрации, без чекбокса согласия и без поля имени.
1. Email, кнопка «Отправить код». **Всегда показывать переход на шаг 2, даже если email не существует** (не раскрываем наличие аккаунта). [ДОПУЩЕНИЕ, логично следует из решения 5.1]
2. Код, с теми же сценариями, что в 5.2.
3. Новый пароль + повтор + тот же чеклист. Успех: завершить все остальные сессии, залогинить, toast «Пароль обновлён».

### 5.4 Юридические страницы
`/privacy` и `/terms` — простые текстовые страницы. Тексты пишет владелец продукта, сейчас ставь заглушку «Текст скоро появится».

## 6. Главная `/`

Назначение: ежедневный вход. «Где я в неделе и что сделать сегодня».

### 6.1 Шапка
- Надзаголовок (серый, `heading-4` цветом `text/tertiary`): «Доброе утро, {имя}». Варианты по времени: 05:00–11:59 «Доброе утро», 12:00–17:59 «Добрый день», 18:00–22:59 «Добрый вечер», 23:00–04:59 «Доброй ночи».
- Заголовок (`heading-1`): «Сегодня вторник · 15 сентября · 14:37». Время обновляется раз в минуту.

### 6.2 KPI, ряд из 4 карточек одинаковой высоты
| Карточка | Значение | Стиль |
|---|---|---|
| прогресс недели | `X%` (формула в разделе 10) | **Инверсная:** фон `bg/inverse`, текст `text/inverse`. Главный акцент экрана |
| цели недели | `выполнено/всего` | `bg/secondary` |
| задачи сегодня | `выполнено/всего` | `bg/secondary` |
| привычки сегодня | `выполнено/всего` | `bg/secondary` |

Цифры шрифтом IBM Plex Mono.

### 6.3 Секции (одна колонка, во всю ширину, друг под другом) [РЕШЕНО]
Две колонки запрещены: высота списков разная и низ получается рваным.

1. **Цели недели.** Справа в заголовке дропдаун с неделей («14.09–20.09»). Список целей и «+ Добавить цель».
2. **Задачи на сегодня.** Справа дропдаун с датой («15.09»), позволяет посмотреть задачи другого дня. Список и «+ Добавить задачу».
3. **Привычки сегодня.** Справа дропдаун с датой. Список: чекбокс, название, справа «N дней» + иконка `flame` (зелёная, если выполнено сегодня, иначе `text/tertiary`). Внизу «+ Добавить привычку».

Изменения на Главной и на Неделе — это одни и те же данные, синхронизировать мгновенно.

## 7. Неделя `/week/:isoWeek`

### 7.1 Шапка
- «Неделя» (`heading-1`).
- Справа: week switcher (пилюля) и кнопка «+ Неделя» (primary).
- **[ОТКРЫТО]** «+ Неделя». По умолчанию: переходит на ближайшую неделю после текущей, в которой ещё нет задач, и подсвечивает её. Недели — это календарные недели, отдельная сущность «неделя» в БД нужна только для хранения целей.

### 7.2 Цели недели
Как на Главной, без дропдауна (неделя задаётся шапкой).

### 7.3 Карточки дней
- 7 карточек Пн–Вс, фиксированная ширина 150px, **горизонтальный скролл** со **стрелками-кнопками** по бокам (круглые, белые, с границей). Стрелка скроллит на ширину одной карточки, у краёв неактивна. Если все карточки влезают, стрелки скрыты. [РЕШЕНО]
- При открытии текущей недели автоскролл к сегодняшнему дню.
- Шапка карточки: «ПН» слева, число месяца справа (IBM Plex Mono).

**Три состояния дня:**
| Состояние | Донат | Задачи | Добавление |
|---|---|---|---|
| Прошедший | % выполнения | можно отмечать задним числом | доступно |
| Сегодня | % выполнения, у карточки граница 1.5px `accent/default`, число жирное | обычный режим | доступно |
| Будущий | пунктирное кольцо, в центре «план» | **можно планировать заранее** [РЕШЕНО], чекбоксы доступны | доступно |

Если у дня 0 задач: донат с прочерком «—» вместо «0%», текст «Пока пусто».

### 7.4 Аналитика недели
Секция с 6 stat-карточками в ряд. **Считается по всей неделе, включая будущие дни.** [РЕШЕНО]
| Карточка | Формула |
|---|---|
| всего задач | количество задач за 7 дней |
| выполнено | количество выполненных |
| осталось | всего − выполнено (подпись именно «осталось», не «не выполнено») [РЕШЕНО] |
| средний прогресс | `выполнено / всего × 100%`, округлить до целого [РЕШЕНО] |
| продуктивный день | день недели («пн») с максимальным % среди прошедших и сегодняшнего дня, у которых есть задачи. При равенстве берётся более ранний. Если таких нет: «—» |
| завершено целей | количество выполненных целей недели |

Графика «план/факт» нет. [РЕШЕНО: убран]

## 8. Привычки `/habits`

Привычки — отдельный домен, они не привязаны к неделям. [РЕШЕНО]

### 8.1 Шапка
«Привычки» (`heading-1`), справа кнопка «+ Добавить привычку» (primary).

### 8.2 Список: аккордеон [РЕШЕНО]
Каждая привычка — карточка `bg/secondary`. Сортировка: не выполненные сегодня сверху, выполненные снизу.

**Свёрнутое состояние:**
- Круглый чекбокс 32px (отметка за сегодня; клик по чекбоксу не раскрывает карточку).
- Название (`heading-5`). Если выполнено сегодня, то зачёркнуто и серое.
- Подстрока: «текущая серия N дней · лучшая M дней» + иконка `flame`.
  - Выполнено сегодня: подстрока и иконка зелёные (`habit/streak-accent`).
  - Не выполнено: `text/tertiary`.
  - Склонение: 1 день, 2–4 дня, 5+ дней (используй функцию плюрализации).
- Справа шеврон вниз. Клик по любой части карточки, кроме чекбокса, раскрывает её.

**Развёрнутое состояние** (раскрывается на месте, без перехода на другую страницу):
- В шапке справа иконка-кнопка «редактировать» и шеврон вверх.
- 4 stat-карточки в ряд: **текущая серия**, **лучшая серия**, **всего выполнено**, **цель** («Каждый день»).
- **Хитмап «История за год»** в белой карточке:
  - Справа в заголовке дропдаун года (по умолчанию текущий; в списке только годы, где привычка существовала).
  - Сетка: столбцы — недели года, строки — дни **Пн–Вс** (неделя с понедельника).
  - Подписи месяцев сверху, над первым столбцом, где начинается месяц.
  - Подписи дней недели **и слева, и справа** (Пн, Вт, Ср, Чт, Пт, Сб, Вс), чтобы при скролле не терять ориентацию. [РЕШЕНО]
  - Ячейка ~14px, зазор 3px, радиус 3px.
  - **Бинарные состояния, без градиента интенсивности** [РЕШЕНО]:
    - выполнено: `accent/default`
    - не выполнено: `bg/tertiary`
    - сегодня: граница 1.5px `accent/default`
    - будущее, дни другого года, дни до создания привычки: пусто (ячейка не рисуется)
  - Первая неделя года неполная: например, 1 января 2026 — четверг, значит Пн–Ср первого столбца пустые. Строй сетку по реальному календарю.
  - Горизонтальный скролл, при открытии скролл к текущему месяцу.
  - Клик по прошлой ячейке переключает выполнение за этот день (исправление задним числом). Будущие ячейки не кликаются. Tooltip на hover: «15 сентября · выполнено».
- Можно раскрыть несколько карточек одновременно.

### 8.3 Создание и редактирование привычки (модалка)
- Поля: Название (обязательно, до 60 символов).
- Цель: пока только «Каждый день». [ДОПУЩЕНИЕ] Заложить в модели поле `frequency` под будущие варианты.
- В режиме редактирования внизу слева ghost-кнопка «Архивировать».

### 8.4 Архив и восстановление [РЕШЕНО: удаление с восстановлением]
- «Архивировать» убирает привычку из списка и показывает toast «Привычка в архиве» с кнопкой «Отменить».
- Внизу экрана ссылка «Архив (N)» открывает список архивных привычек. У каждой две кнопки: «Восстановить» (возвращает со всей историей) и «Удалить навсегда» (с модалкой подтверждения).
- Архивные привычки не показываются на Главной и не учитываются в KPI.

Колонка шириной до 560px. Фото и аватара нет. [РЕШЕНО]

## 10. Бизнес-логика и формулы

Все расчёты в часовом поясе пользователя (из браузера). День начинается в 00:00.

| Метрика | Формула |
|---|---|
| % дня | `выполненные задачи дня / все задачи дня`. Если задач 0, то `null` (показывать «—», не 0%) |
| Прогресс недели (Главная) | `выполненные задачи недели / все задачи недели`, **включая будущие дни** |
| Средний прогресс (Неделя) | то же, что прогресс недели |
| Цели недели | `выполненные цели / все цели недели` |
| Задачи сегодня | `выполненные задачи сегодня / все задачи сегодня` |
| Привычки сегодня | `привычки, отмеченные сегодня / все активные (не архивные) привычки` |
| Текущая серия | количество подряд идущих выполненных дней, заканчивая сегодня. **Если сегодня ещё не отмечено, серия считается до вчера включительно и не обнуляется до конца дня** |
| Лучшая серия | максимальная серия за всю историю привычки |
| Всего выполнено | количество отметок привычки за всю историю |

Округление процентов до целого: `Math.round`.

## 11. Добавление и редактирование задач и целей

Отдельных модалок не нужно. **Инлайн-паттерн** [ДОПУЩЕНИЕ]:
- Клик по «+ Добавить задачу» превращает кнопку в инпут с автофокусом.
- Enter сохраняет, создаёт элемент и оставляет новый пустой инпут для быстрого ввода следующего.
- Esc или потеря фокуса с пустым полем отменяют ввод.
- Максимум 200 символов.
- Редактирование: клик по тексту невыполненного элемента или иконка карандаша на hover. Тот же инлайн-инпут.
- Удаление: иконка корзины на hover, удаляет сразу и показывает toast «Задача удалена» с кнопкой «Отменить» (5 секунд).
- Перенос задачи на другой день: [ОТКРЫТО] вне скоупа v1, но в модели данных у задачи есть поле `date`.

## 13. Модель данных (Postgres)

```sql
profiles (
  id uuid pk references auth.users,
  name text not null,
  consent_accepted_at timestamptz not null,
  consent_version text not null,
  password_changed_at timestamptz,
  created_at timestamptz default now()
)

goals (
  id uuid pk,
  user_id uuid fk,
  week_start date not null,        -- понедельник недели
  title text not null,
  is_done boolean default false,
  done_at timestamptz,
  created_at timestamptz default now()
)

tasks (
  id uuid pk,
  user_id uuid fk,
  date date not null,
  title text not null,
  is_done boolean default false,
  done_at timestamptz,
  created_at timestamptz default now()
)

habits (
  id uuid pk,
  user_id uuid fk,
  title text not null,
  frequency text default 'daily',
  archived_at timestamptz,         -- null = активна
  created_at timestamptz default now()
)

habit_checks (
  habit_id uuid fk on delete cascade,
  date date not null,
  primary key (habit_id, date)
)
```

- Row Level Security: каждый пользователь видит только свои строки (`user_id = auth.uid()`).
- Серии считаются на лету из `habit_checks`. Кешировать не нужно.
- Удаление аккаунта каскадно удаляет все данные.

## 14. Общие требования

- **Оптимистичные обновления** для чекбоксов: UI меняется сразу, при ошибке откат и toast «Не удалось сохранить».
- Загрузка: скелетоны в форме будущих блоков, без спиннеров на весь экран.
- Доступность: все интерактивные элементы доступны с клавиатуры, видимый focus-ring, у иконок-кнопок есть `aria-label`.
- Формат дат: «15 сентября», «14–20 сентября 2026», короткие «15.09», «14.09–20.09».

### 14.1 Правила текстов в интерфейсе
- Русский, на «ты», коротко и просто.
- **Без длинных тире (—) в текстах интерфейса.** Вместо них точка, двоеточие или запятая. Исключение: прочерк «—» как значение пустой метрики.
- Без канцелярита и «пожалуйста». Без восклицательных знаков в системных сообщениях.
- Кнопки начинаются с глагола: «Добавить», «Сохранить», «Удалить».
